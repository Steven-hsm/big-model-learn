## 三、详细学习内容

### Day 1: 数据管线设计 (2h)

#### ML数据管线的5个阶段

```
采集(Ingestion) → 清洗(Cleaning) → 转换(Transform) → 特征计算(Feature) → 存储(Serving)
```

**阶段1 - 数据采集**:
- 数据源类型：数据库(MySQL/PostgreSQL)、API接口、文件系统(CSV/Parquet)、流式数据(Kafka)
- 采集策略：全量采集（首次）、增量采集（定时CDC变更捕获）

**阶段2 - 数据清洗**:
- 缺失值处理（删除/填充/插值）
- 异常值检测（IQR/Z-score/孤立森林）
- 重复数据去重
- 数据类型转换与标准化

**阶段3 - 数据转换**:
- 格式统一（日期格式/编码格式/单位转换）
- 数据合并（Join多个数据源）
- 数据聚合（GroupBy统计）

**阶段4 - 特征计算**:
- 原始特征提取
- 衍生特征计算（交叉特征/统计特征/时间特征）
- 特征编码（OneHot/Label/Target Encoding）

**阶段5 - 特征存储**:
- 离线存储（数据仓库/数据湖，用于训练）
- 在线存储（Redis/MySQL，用于实时推理）

#### 批处理 vs 流处理Pipeline

| 维度 | 批处理Pipeline | 流处理Pipeline |
|------|---------------|---------------|
| 数据范围 | 全量数据 | 增量数据 |
| 延迟 | 分钟~小时级 | 毫秒~秒级 |
| 触发方式 | 定时调度(cron) | 事件驱动 |
| 适用场景 | 模型训练特征计算 | 在线推理实时特征 |
| 工具 | Airflow/Spark | Kafka/Flink |
| 示例 | 每天凌晨计算用户画像 | 用户点击后实时更新推荐特征 |

```python
import great_expectations as gx
import pandas as pd

# 获取数据上下文
context = gx.get_context()

# 创建数据源和数据资产
datasource = context.sources.add_pandas("my_datasource")
asset = datasource.add_dataframe_asset(name="my_asset")

# 创建Expectation Suite
suite = context.add_expectation_suite("my_suite")

# 定义各种质量规则
# 规则1：列值不为空
suite.add_expectation(
    gx.expectations.ExpectColumnValuesToNotBeNull(column="user_id")
)

# 规则2：列值在指定范围内
suite.add_expectations([
    gx.expectations.ExpectColumnValuesToBeBetween(
        column="age",
        min_value=0,
        max_value=150
    ),
    gx.expectations.ExpectColumnValuesToBeInSet(
        column="gender",
        value_set=["M", "F", "Other"]
    ),
])

# 规则3：列值唯一
suite.add_expectation(
    gx.expectations.ExpectColumnValuesToBeUnique(column="email")
)

# 规则4：表行数在合理范围
suite.add_expectation(
    gx.expectations.ExpectTableRowCountToBeBetween(
        min_value=100,
        max_value=1000000
    )
)

# 规则5：列值匹配正则表达式
suite.add_expectation(
    gx.expectations.ExpectColumnValuesToMatchRegex(
        column="phone",
        regex=r"^\d{11}$"
    )
)

# 规则6：列值类型
suite.add_expectation(
    gx.expectations.ExpectColumnValuesToBeOfType(
        column="price",
        type_="float"
    )
)

context.add_or_update_expectation_suite(suite)
```

#### 自动化质量检查脚本

```python
# data_quality_check.py
import great_expectations as gx
import pandas as pd
import sys

def check_data_quality(csv_path: str, suite_name: str = "default_suite") -> bool:
    """数据质量检查函数"""
    # 读取数据
    df = pd.read_csv(csv_path)
    print(f"数据集大小: {df.shape}")

    # 获取上下文
    context = gx.get_context()

    # 创建数据源
    datasource = context.sources.add_pandas("quality_check")
    asset = datasource.add_dataframe_asset(name="data")
    batch_request = asset.build_batch_request(dataframe=df)

    # 运行检查点
    checkpoint = context.add_or_update_checkpoint(
        name="quality_checkpoint",
        validations=[{
            "batch_request": batch_request,
            "expectation_suite_name": suite_name,
        }]
    )
    result = checkpoint.run()

    # 输出结果
    stats = result["statistics"]
    print(f"\n===== 数据质量报告 =====")
    print(f"总检查项: {stats['evaluated_expectations']}")
    print(f"通过: {stats['successful_expectations']}")
    print(f"失败: {stats['unsuccessful_expectations']}")
    print(f"通过率: {stats['successful_expectations']/stats['evaluated_expectations']*100:.1f}%")

    # 生成HTML报告
    context.build_data_docs()

    return result["success"]

if __name__ == "__main__":
    success = check_data_quality("data/raw.csv")
    sys.exit(0 if success else 1)  # 失败返回非0，可用于CI/CD
```

### Day 4: Feature Store (2h)

#### Feature Store概念

```
核心问题：训练-推理特征不一致（Training-Serving Skew）

训练时：用Python批处理计算特征（如：用户最近30天消费总额）
推理时：用Java实时计算同一特征（逻辑不同、数据源不同）

结果：模型上线后效果大打折扣

Feature Store的解决方案：
- 统一管理特征定义（只定义一次）
- 同时支持离线批量读取（训练）和在线实时读取（推理）
- 保证训练和推理使用完全相同的特征计算逻辑

┌──────────────┐
│  Feature      │
│  Store        │
│               │
│  ┌─────────┐  │     离线特征（批量计算）
│  │ Offline  │───────▶ 存数据仓库/数据湖
│  │ Store   │  │     用于模型训练
│  └─────────┘  │
│               │
│  ┌─────────┐  │     在线特征（实时计算）
│  │ Online   │───────▶ 存Redis/MySQL
│  │ Store   │  │     用于在线推理
│  └─────────┘  │
│               │
│  特征定义      │  ← 统一的特征元数据
│  (FeatureView)│
└──────────────┘
```

```python
from datetime import timedelta
from feast import Entity, FeatureView, Field, FileSource
from feast.types import Float64, Int64, String

# 定义数据源（离线数据）
user_stats_source = FileSource(
    name="user_stats_source",
    path="data/user_stats.parquet",  # 离线数据路径
    timestamp_field="event_timestamp",
    created_timestamp_column="created_timestamp",
)

# 定义实体（类似数据库的主键）
user = Entity(
    name="user_id",
    join_keys=["user_id"],  # join键
    description="用户ID",
)

# 定义FeatureView（特征视图）
user_stats_fv = FeatureView(
    name="user_stats",              # 特征视图名称
    entities=[user],                # 关联的实体
    ttl=timedelta(days=7),          # 特征有效期
    schema=[                        # 特征列表
        Field(name="total_spend_30d", dtype=Float64),
        Field(name="order_count_30d", dtype=Int64),
        Field(name="avg_order_value", dtype=Float64),
        Field(name="user_level", dtype=String),
    ],
    online=True,                    # 启用在线存储
    source=user_stats_source,       # 数据源
    tags={"team": "recommendation"}, # 标签
)
```

#### 特征选择流水线

```python
from sklearn.feature_selection import VarianceThreshold, mutual_info_classif
from sklearn.preprocessing import StandardScaler
import numpy as np

# 步骤1：方差阈值（删除方差过小的特征，几乎不变的特征无用）
selector1 = VarianceThreshold(threshold=0.01)
X_high_var = selector1.fit_transform(feature_matrix.fillna(0))
print(f"方差阈值筛选: {feature_matrix.shape[1]} -> {X_high_var.shape[1]}")

# 步骤2：相关系数（删除高度相关的冗余特征）
corr_matrix = pd.DataFrame(X_high_var).corr().abs()
upper = corr_matrix.where(np.triu(np.ones(corr_matrix.shape), k=1).astype(bool))
to_drop = [column for column in upper.columns if any(upper[column] > 0.95)]
print(f"高相关删除: {len(to_drop)} 个特征")

# 步骤3：互信息（与目标变量的非线性相关性）
mi_scores = mutual_info_classif(X_high_var, y_train)
mi_series = pd.Series(mi_scores, index=range(X_high_var.shape[1]))
mi_series = mi_series.sort_values(ascending=False)
```

#### 主动学习（Active Learning）

```python
import numpy as np
from sklearn.model_selection import train_test_split

class ActiveLearner:
    """主动学习：选择模型最不确定的样本优先标注"""

    def __init__(self, model, unlabeled_data, initial_labeled_size=100):
        self.model = model
        self.unlabeled_data = unlabeled_data
        # 随机选择初始标注集
        self.labeled_indices = np.random.choice(
            len(unlabeled_data), initial_labeled_size, replace=False
        )

    def uncertainty_sampling(self, n_samples=50):
        """不确定性采样策略"""
        # 获取未标注数据
        mask = np.ones(len(self.unlabeled_data), dtype=bool)
        mask[self.labeled_indices] = False
        unlabeled_idx = np.where(mask)[0]

        # 用当前模型预测概率
        X_unlabeled = self.unlabeled_data[unlabeled_idx]
        probas = self.model.predict_proba(X_unlabeled)

        # 计算不确定性（熵）
        entropy = -np.sum(probas * np.log(probas + 1e-10), axis=1)

        # 选择最不确定的n个样本
        uncertain_indices = unlabeled_idx[np.argsort(entropy)[-n_samples:]]
        return uncertain_indices

    def iterative_train(self, X, y, n_iterations=5, n_samples_per_iter=50):
        """迭代训练"""
        for i in range(n_iterations):
            # 训练当前模型
            self.model.fit(X[self.labeled_indices], y[self.labeled_indices])

            # 选择最不确定的样本
            new_indices = self.uncertainty_sampling(n_samples_per_iter)

            # 模拟人工标注（实际中需要人工标注）
            # labeled_y[new_indices] = human_annotate(new_indices)

            # 加入已标注集
            self.labeled_indices = np.concatenate([
                self.labeled_indices, new_indices
            ])

            # 评估当前模型
            score = self.model.score(X_test, y_test)
            print(f"迭代 {i+1}: 标注样本数={len(self.labeled_indices)}, 准确率={score:.4f}")
```

```python
# src/quality_check.py
import great_expectations as gx
import pandas as pd

def run_quality_check(df: pd.DataFrame, dataset_name: str = "default") -> bool:
    """运行数据质量检查"""
    context = gx.get_context(mode="ephemeral")

    # 创建数据源
    datasource = context.sources.add_pandas(dataset_name)
    asset = datasource.add_dataframe_asset(name="data")
    batch_request = asset.build_batch_request(dataframe=df)

    # 创建Expectation Suite
    suite = context.add_expectation_suite(f"{dataset_name}_suite")

    # 添加基本检查规则
    expectations = [
        gx.expectations.ExpectTableRowCountToBeBetween(min_value=1, max_value=10_000_000),
    ]

    # 对数值列添加范围检查
    for col in df.select_dtypes(include="number").columns:
        expectations.append(
            gx.expectations.ExpectColumnValuesToNotBeNull(column=col, mostly=0.9)
        )

    # 对分类列添加唯一性检查
    if "customer_id" in df.columns:
        expectations.append(
            gx.expectations.ExpectColumnValuesToBeUnique(column="customer_id")
        )

    for exp in expectations:
        suite.add_expectation(exp)
    context.add_or_update_expectation_suite(suite)

    # 运行检查
    checkpoint = context.add_or_update_checkpoint(
        name=f"{dataset_name}_checkpoint",
        validations=[{
            "batch_request": batch_request,
            "expectation_suite_name": f"{dataset_name}_suite",
        }]
    )
    result = checkpoint.run()

    stats = result["statistics"]
    passed = stats["successful_expectations"]
    total = stats["evaluated_expectations"]
    print(f"质量检查: {passed}/{total} 通过")

    return result["success"]
```

```python
# src/data_cleaner.py
import pandas as pd
import numpy as np

def clean_data(df: pd.DataFrame) -> pd.DataFrame:
    """数据清洗"""
    original_len = len(df)

    # 1. 删除完全重复的行
    df = df.drop_duplicates()
    print(f"删除重复行: {original_len - len(df)}")

    # 2. 处理缺失值
    for col in df.columns:
        missing_count = df[col].isnull().sum()
        if missing_count > 0:
            if df[col].dtype in ["float64", "int64"]:
                # 数值列用中位数填充
                df[col].fillna(df[col].median(), inplace=True)
                print(f"  {col}: 用中位数填充 {missing_count} 个缺失值")
            else:
                # 分类列用众数填充
                df[col].fillna(df[col].mode()[0], inplace=True)
                print(f"  {col}: 用众数填充 {missing_count} 个缺失值")

    # 3. 处理异常值（IQR方法）
    for col in df.select_dtypes(include="number").columns:
        Q1 = df[col].quantile(0.25)
        Q3 = df[col].quantile(0.75)
        IQR = Q3 - Q1
        lower = Q1 - 1.5 * IQR
        upper = Q3 + 1.5 * IQR
        outliers = ((df[col] < lower) | (df[col] > upper)).sum()
        if outliers > 0:
            df[col] = df[col].clip(lower, upper)
            print(f"  {col}: 截断 {outliers} 个异常值")

    return df
```

```python
# src/feature_engineer.py
import pandas as pd
import numpy as np

def compute_features(df: pd.DataFrame) -> pd.DataFrame:
    """计算特征"""
    features = pd.DataFrame()

    # 保留ID列
    if "customer_id" in df.columns:
        features["customer_id"] = df["customer_id"]

    # 复制原始数值特征
    numeric_cols = df.select_dtypes(include="number").columns.tolist()
    for col in numeric_cols:
        if col != "customer_id":
            features[col] = df[col]

    # 时间特征（如果有日期列）
    date_cols = df.select_dtypes(include="datetime").columns.tolist()
    for col in date_cols:
        features[f"{col}_year"] = df[col].dt.year
        features[f"{col}_month"] = df[col].dt.month
        features[f"{col}_dayofweek"] = df[col].dt.dayofweek
        features[f"{col}_is_weekend"] = (df[col].dt.dayofweek >= 5).astype(int)

    # 交叉特征
    if "total_spend" in df.columns and "order_count" in df.columns:
        features["avg_order_value"] = df["total_spend"] / (df["order_count"] + 1)

    # 统计特征
    for col in numeric_cols:
        if col != "customer_id":
            features[f"{col}_log"] = np.log1p(np.abs(df[col]))

    return features
```

### 参考答案

<details>
<summary>点击展开答案</summary>

1. **Git管理代码**（.py, .yaml等文本文件）和**DVC管理数据**（数据集、模型文件等大文件）。配合方式：DVC生成.dvc文件记录数据的哈希和元信息，这个.dvc文件由Git管理。当需要复现时，先git clone获取代码和.dvc文件，再dvc pull根据.dvc文件从远程存储下载数据。

2. **Feature Store解决训练-推理特征不一致（Training-Serving Skew）问题**。离线特征是批量计算的历史特征，存在数据仓库中，用于模型训练；在线特征是实时计算的特征，存在Redis等低延迟存储中，用于在线推理。两者共享同一个特征定义，确保一致性。

3. Great Expectations支持：列值非空检查、列值范围检查、列值唯一性检查、列值类型检查、列值在集合内检查、正则匹配检查、表行数范围检查、列间关系检查、自定义SQL检查等。

4. 主动学习通过选择模型最不确定的样本来标注，减少不必要的标注。不确定性采样计算每个样本的预测熵（entropy），熵越高表示模型越不确定，优先标注这些样本可以让模型学到更多。相比随机标注，通常可以减少50-80%的标注量。

5. 批处理Pipeline处理全量数据，延迟高（分钟~小时级），适合模型训练特征计算；流处理Pipeline处理增量数据，延迟低（毫秒~秒级），适合在线推理实时特征计算。批处理按时间调度触发，流处理按事件触发。

## 七、Java开发者提示

> 帮助有Java背景的开发者理解ML数据工程概念

| ML数据工程概念 | Java类比 | 说明 |
|--------------|---------|------|
| DVC数据版本管理 | Maven/Gradle的依赖版本管理 | DVC管数据版本，就像Maven管jar包版本 |
| DVC Pipeline | Maven的build lifecycle | dvc.yaml定义stage依赖，类似pom.xml定义build phase |
| Great Expectations | JUnit的Assert断言 | GE检查数据质量，类似JUnit检查代码逻辑 |
| Feature Store | Spring的Service层缓存 | Feature Store统一管理特征，类似Spring Cache统一管理缓存 |
| Feature View | JPA的Entity/Repository | FeatureView定义特征结构，类似@Entity定义数据表映射 |
| Entity (Feast) | JPA的@Entity主键 | Feast的Entity是特征join键，类似JPA的@Id |
| Airflow DAG | Spring Batch的Job/Step | Airflow编排任务，类似Spring Batch编排批处理 |
| Featuretools DFS | Java Stream API的连锁操作 | DFS自动生成组合特征，类似Stream的map/filter/reduce |
| Label Studio | 任何 crowdsourcing 平台 | 数据标注平台，给数据打标签 |
| Active Learning | 二分查找 | 每次选择最有信息量的样本标注，类似二分查找每次排除一半 |
| Prometheus+Grafana | Spring Boot Actuator+监控 | Prometheus采集指标，类似Actuator暴露metrics |
| 数据漂移 | API版本兼容性变化 | 数据分布变化导致模型失效，类似API升级后客户端不兼容 |

### 关键思维转换

1. **数据即代码**: 在ML中，数据和代码同等重要，需要版本管理和质量检查
2. **特征是API**: Feature Store中的特征就像微服务的API，需要稳定、有文档、有版本
3. **Pipeline是流水线**: ML Pipeline类似CI/CD流水线，但处理的是数据而非代码
4. **监控对象不同**: 传统软件监控代码运行状态，ML还需要监控数据分布和模型效果
5. **一致性是关键**: 训练和推理必须使用相同的特征计算逻辑，就像前后端必须使用相同的API契约
