### Day 1: 博客平台选择与搭建 (2h)

#### 平台对比

| 平台 | 优点 | 缺点 | 适合人群 |
|------|------|------|---------|
| 掘金 | 中文社区活跃，推荐机制好，Markdown支持 | SEO不如独立博客 | 中文开发者 |
| 知乎 | 流量大，搜索排名高 | 排版受限 | 技术科普 |
| Medium | 国际化，排版精美 | 英文写作门槛 | 想做国际影响力 |
| Hugo个人博客 | 完全可控，SEO好 | 需要搭建维护 | 有技术基础 |
| CSDN | 流量大 | 广告多，用户体验差 | 短期引流 |
| 微信公众号 | 私域流量 | 排版困难，封闭生态 | 想做自媒体 |

#### 推荐方案

```
最佳组合：掘金/知乎（发布）+ 个人博客（存档）

短期（本周）：先用掘金发布，最快上手
中期（1-2个月后）：搭建Hugo个人博客，文章同步发布
长期：积累足够文章后，精选文章翻译英文发Medium
```

#### Hugo个人博客搭建

```bash
# 1. 安装Hugo
# Windows
choco install hugo-extended
# Mac
brew install hugo

# 2. 创建博客
hugo new site my-tech-blog
cd my-tech-blog

# 3. 安装主题（推荐PaperMod）
git init
git submodule add https://github.com/adityatelange/hugo-PaperMod.git themes/PaperMod

# 4. 配置
cat > hugo.toml << 'EOF'
baseURL = 'https://yourusername.github.io/'
languageCode = 'zh-cn'
title = 'AI技术笔记'
theme = 'PaperMod'

[params]
  description = "从Java到AI的技术转型之路"
  author = "Your Name"

[[menu.main]]
  name = "文章"
  url = "/posts/"
  weight = 1

[[menu.main]]
  name = "标签"
  url = "/tags/"
  weight = 2

[[menu.main]]
  name = "关于"
  url = "/about/"
  weight = 3
EOF

# 5. 创建第一篇文章
hugo new posts/transformer-from-scratch.md

# 6. 本地预览
hugo server -D  # 访问 http://localhost:1313

# 7. 部署到GitHub Pages
hugo  # 生成静态文件到 public/
cd public
git init
git remote add origin https://github.com/yourusername/yourusername.github.io.git
git add .
git commit -m "initial blog"
git push -u origin main
```

```
       - 残差连接

4. 实验验证（500字）
```

#### 写作技巧

```
技术文章写作5条法则：

1. 标题要具体
   ❌ "Transformer详解"
   ✅ "用200行NumPy代码实现Transformer：从数学原理到代码"

2. 开头要有钩子
   ❌ "本文介绍Transformer的原理"
   ✅ "你有没有好奇过ChatGPT背后的核心算法？今天我们不用任何框架，从零实现它"

3. 代码要有注释
   - 每个函数都有docstring
   - 关键步骤有行内注释
   - 维度变化用注释标注
   # x shape: (batch, seq_len, d_model)
   # q shape: (batch, seq_len, d_k)

4. 图文结合
   - 架构图
   - 维度变化示意图
   - 训练曲线图
   - 每个复杂概念配一张图

5. 提供完整可运行代码
   - 读者可以复制粘贴直接运行
   - 提供Colab链接
   - 附带示例输入输出
```

### Day 3: 写实战经验文章 (2h)

#### 选题：RAG系统踩坑指南

```
写作框架：

1. 引言（200字）
   - RAG很火但坑很多
   - 本文分享实际开发中遇到的10个问题和解决方案

2. 问题与解决方案（2000字）

   坑1：文档切分太机械，上下文断裂
   问题：按固定长度切分，一个完整的段落被切到两个chunk
   解决：使用MarkdownHeaderSplitter + 语义切分
   数据：固定切分 Recall@5=62% → 智能切分 Recall@5=84%

   坑2：只用向量检索，关键词匹配不到
   问题：用户搜"BERT"，向量检索匹配不到（因为语义上BERT和"预训练模型"更相关）
   解决：向量检索 + BM25混合检索 + RRF融合
   数据：纯向量 Recall@5=71% → 混合检索 Recall@5=89%

   坑3：Embedding模型选择不当
   问题：用了通用英文模型处理中文文档
   解决：切换到BGE-large-zh，中文效果大幅提升
   数据：英文模型 Recall@5=55% → BGE-zh Recall@5=85%

   坑4：LLM幻觉严重，编造文档中没有的内容
   问题：LLM在没有相关上下文时编造答案
   解决：优化Prompt + 设置低temperature + 添加"无法回答"选项
   数据：幻觉率从23%降低到5%

   坑5：检索速度太慢
   问题：每个查询需要2-3秒，用户体验差
   解决：Embedding缓存 + Redis LLM缓存
   数据：P95延迟从2.8s降低到0.4s

   ...（可以继续写到10个）

3. 总结建议（300字）
   - 先用最简方案跑通MVP
   - 用数据驱动优化决策
   - 评估体系要先行

4. 架构图与数据对比表
```

### 参考答案

<details>
<summary>点击展开答案</summary>

1. **选题考虑因素**：(1) **自身经验** - 写你真正做过的、踩过的坑，比纯翻译有价值得多。(2) **读者需求** - 选题是否解决了一个常见的痛点？搜索量如何？(3) **独特视角** - 是否有你的独特见解或数据支撑？(4) **时效性** - 是否与当前技术热点相关？(5) **深度** - 能否写到足够的深度，而不是泛泛而谈？判断标准：如果你能在一篇文章中提供3个以上"干货"（数据对比、踩坑经验、独特见解），就值得写。

2. **README关键要素**：(1) **一句话介绍** - 项目做什么，解决什么问题。(2) **功能特性列表** - 核心功能简述。(3) **快速开始** - 3步以内能运行起来（安装→配置→运行）。(4) **Demo截图/GIF** - 可视化展示项目效果。(5) **架构图** - 展示系统设计。(6) **技术栈** - 使用的技术列表。(7) **API文档链接** - 详细的接口文档。(8) **部署指南** - 如何部署到生产环境。(9) **性能数据** - 关键指标和对比数据。(10) **License** - 开源许可证。(11) **徽章** - CI状态、版本号、代码覆盖率等。

3. **社区参与价值**：(1) **技术成长** - 回答问题和讨论可以加深理解，接触到不同视角和最佳实践。(2) **人脉建设** - 认识志同道合的开发者，可能带来合作机会、内推机会。(3) **可见度提升** - 活跃的社区参与让更多人认识你，增加被招聘者发现的机会。(4) **信息优势** - 第一时间获取新技术动态和行业趋势。(5) **软技能锻炼** - 沟通表达、技术写作、协作能力都得到锻炼。(6) **开源声誉** - 在知名项目的贡献记录是能力的直接证明。

4. **个人品牌策略**：(1) **持续输出** - 保持每周至少一篇技术文章，形成节奏感。质量稳定比偶尔的爆款更重要。(2) **聚焦定位** - 不要什么都写，聚焦1-2个领域（如RAG系统、AI工程化），成为这个领域的专家形象。(3) **多渠道同步** - 文章在掘金、知乎、个人博客同步发布，扩大覆盖面。(4) **数据驱动** - 用实际数据和对比展示技术能力，而不是空洞的概念。(5) **互动交流** - 积极回复评论，参与讨论，关注同领域的其他作者。(6) **长期主义** - 个人品牌建设是1-3年的长期投入，不要期望短期爆发。
</details>
