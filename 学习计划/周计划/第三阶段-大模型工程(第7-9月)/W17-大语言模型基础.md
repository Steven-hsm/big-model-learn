### Day 1: LLM架构演进

#### 3.1.1 GPT系列演进

**GPT-1 (2018)**
- 论文：《Improving Language Understanding by Generative Pre-Training》
- 参数量：1.17亿
- 核心创新：无监督预训练 + 有监督微调的两阶段范式
- 架构：Transformer Decoder（仅保留Masked Self-Attention）
- 预训练任务：给定前文，预测下一个词（Next Token Prediction）

**GPT-2 (2019)**
- 论文：《Language Models are Unsupervised Multitask Learners》
- 参数量：15亿（1.5B）
- 核心创新：零样本学习（Zero-shot Learning），不需要微调就能做下游任务
- 关键理念：一个足够大的语言模型本身就是一个多任务学习器
- 训练数据：WebText（40GB高质量网页文本）

**GPT-3 (2020)**
- 论文：《Language Models are Few-Shot Learners》
- 参数量：1750亿（175B）
- 核心创新：少样本学习（In-Context Learning），在Prompt中给几个示例模型就能学会
- 三种学习模式：
  - Zero-shot：`"Translate to French: Hello"` → `"Bonjour"`
  - One-shot：给1个示例
  - Few-shot：给几个示例
- API化：OpenAI开始以API方式提供服务

**GPT-4 (2023)**
- 核心创新：多模态（文本+图像输入）
- 特点：推理能力大幅提升、在各类考试中达到人类顶级水平
- 安全性：经过RLHF对齐训练

#### 3.1.2 BERT (2018)

- 论文：《BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding》
- 架构：Transformer Encoder（双向注意力）
- 参数量：BERT-Base 110M / BERT-Large 340M
- 预训练任务：
  - **MLM (Masked Language Model)**：随机遮���15%的token，预测被遮盖的词
  - **NSP (Next Sentence Prediction)**：判断两个句子是否相邻
- 擅长任务：文本分类、命名实体识别、问答系统、情感分析
- 与GPT的核心区别：

```
| 特征       | GPT (Decoder-Only)      | BERT (Encoder-Only)     |
|-----------|------------------------|------------------------|
| 注意力方向 | 单向（只看前文）         | 双向（看前后文）         |
| 预训练任务 | 预测下一个词             | MLM + NSP              |
| 擅长任务   | 文本生成                 | 文本理解               |
| 输出方式   | 自回归逐词生成           | 一次性编码整句           |
```

#### 3.1.3 开源LLM代表

**LLaMA (Meta, 2023)**
- 参数规模：7B / 13B / 33B / 65B
- 核心贡献：证明小模型用更多数据训练可以达到大模型效果
- LLaMA 2：7B / 13B / 70B，支持商用
- LLaMA 3：8B / 70B / 405B

**Mistral**
- Mistral 7B：参数量小但性能卓越
- Mixtral 8x7B：SMoE（稀疏混合专家）架构
  - 8个专家网络，每个token只激活2个专家
  - 总参数量46.7B，但每次推理只用12.9B参数

**Qwen (阿里通义千问)**
- Qwen2 / Qwen2.5系列
- 多语言支持好，中文能力突出
- 多种规模：0.5B / 1.5B / 7B / 14B / 72B

**DeepSeek**
- DeepSeek-V2：MoE架构，推理成本低
- DeepSeek-Coder：代码能力突出
- DeepSeek-R1：推理能力强

#### 3.1.4 Chinchilla Scaling Law

核心发现：给定计算预算C，最优模型大小N和训练数据量D满足：

```
C ≈ 6ND
N_opt ∝ C^0.5
D_opt ∝ C^0.5
```

含义：
- 模型大小和训练数据量应该等比例增长
- 之前的LLM（如GPT-3）模型太大而数据太少
- Chinchilla（70B参数，1.4T数据）超过Gopher（280B参数，300B数据）
- 这解释了为什么LLaMA用更多数据训练小模型也能有好效果

### Day 2: Tokenizer深入

#### 3.2.1 BPE (Byte Pair Encoding) 算法

GPT系列使用的分词算法，步骤如下：

**Step 1：初始化基础词表**
```
基础词表 = 所有单个字符
例如：{"a", "b", "c", "d", "e", "h", "l", "o", " "}
```

**Step 2：统计相邻pair频率**
```
语料: ["low", "lower", "newest", "widest"]
统计所有相邻token对的频率:
("l", "o") -> 2
("o", "w") -> 2
("w", "e") -> 2
("e", "r") -> 1
("e", "s") -> 2
("s", "t") -> 2
...
```

**Step 3：合并最高频pair**
```
最高频pair: ("e", "s") -> 合并为 "es"
新词表加入 "es"
语料变为: ["low", "low" "er", "n" "ew" "est", "wid" "est"]
```

**Step 4：重复Step 2-3直到词表大小达标**

#### 3.2.3 Token数量对费用和上下文的影响

```
| 模型           | 输入价格(/1M tokens) | 输出价格(/1M tokens) | 上下文长度 |
|---------------|---------------------|---------------------|-----------|
| GPT-4o        | $2.50               | $10.00              | 128K      |
| GPT-4o-mini   | $0.15               | $0.60               | 128K      |
| Claude Sonnet | $3.00               | $15.00              | 200K      |
| Claude Haiku  | $0.25               | $1.25               | 200K      |
```

**关键认知**：
- 1个汉字 ≈ 1-2个tokens（中文Token效率较低）
- 1个英文单词 ≈ 1-1.5个tokens
- API费用 = (输入token数 x 输入单价 + 输出token数 x 输出单价)
- 超出上下文长度的对话会被截断

#### 3.2.4 特殊Token

```
| Token       | 用途                      | 使用模型     |
|-------------|--------------------------|-------------|
| [CLS]       | 句首，分类任务取该位置输出    | BERT        |
| [SEP]       | 句子分隔符                  | BERT        |
| [PAD]       | 填充，使batch内序列等长      | BERT        |
| [MASK]      | MLM任务中被遮盖的位置        | BERT        |
| <|endoftext|> | 文本结束/文档分隔         | GPT系列     |
| <s>         | 序列开始                   | LLaMA       |
| </s>        | 序列结束                   | LLaMA       |
```

#### 3.4.2 Tree-of-Thought (ToT)

探索多个推理路径，选择最优：

```
              问题
            /  |  \
        路径1 路径2 路径3   ← 生成多个候选推理方向
         |     |     |
        评估  评估   评估    ← 评估每个路径的可行性
         |     |
      继续  继续             ← 选择最有前景的路径继续
       |
     最终答案
```

```python
tot_prompt = """解决问题：{problem}

请生成3个不同的推理方向：
方向1：
方向2：
方向3：

评估每个方向的可行性（1-10分）：
方向1评分：_ 原因：_
方向2评分：_ 原因：_
方向3评分：_ 原因：_

选择得分最高的方向继续推理，得出最终答案。"""
```

#### 3.4.3 Self-Consistency

多次采样CoT，投票选最多的答案：

```python
import openai

def self_consistency(question, n_samples=5):
    """多次采样，投票选择最一致的答案"""
    answers = []
    for i in range(n_samples):
        response = openai.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "user", "content": f"Q: {question}\nA: Let's think step by step."}
            ],
            temperature=0.7  # 较高温度产生多样性
        )
        answers.append(response.choices[0].message.content)

    # 从每个回答中提取最终答案
    # 投票选择出现次数最多的答案
    from collections import Counter
    final_answers = [extract_final_answer(a) for a in answers]
    most_common = Counter(final_answers).most_common(1)[0][0]
    return most_common, answers
```

#### 3.4.4 ReAct (Reasoning + Acting)

ReAct为Agent的核心模式铺路：

```
Question: 中国的首都是哪个城市？那里现在的天气怎么样？

Thought 1: 我需要找到中国的首都，然后查询天气。
Action 1: Search[中国首都]
Observation 1: 中国的首都是北京。

Thought 2: 知道了首都是北京，现在查询北京的天气。
Action 2: Weather[北京]
Observation 2: 北京今天晴，温度25°C，湿度45%。

Thought 3: 我已经获得了所有需要的信息。
Answer: 中国的首都是北京。北京今天的天气是晴天，温度25°C，湿度45%。
```

```python
                },
                "required": ["expression"]

        }

    model="gpt-4o",
    messages=[
        {"role": "user", "content": "北京今天天气怎么样？"}

if response.choices[0].message.tool_calls:
    tool_call = response.choices[0].message.tool_calls[0]
    function_name = tool_call.function.name
    function_args = json.loads(tool_call.function.arguments)

    print(f"模型要调用: {function_name}")
    print(f"参数: {function_args}")
    # 输出: 模型要调用: get_weather
    # 参数: {'city': '北京', 'unit': 'celsius'}

    # 执行实际函数
    if function_name == "get_weather":
        result = get_weather(**function_args)  # 你自己实现的函数

    # 将结果返回给模型
    messages = [
        {"role": "user", "content": "北京今天天气怎么样？"},
        response.choices[0].message,  # 模型的工具调用消息
        {
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": json.dumps(result, ensure_ascii=False)
        }
    ]

    # 第二次调用，让模型根据工具结果生成最终回答
    final_response = client.chat.completions.create(
        model="gpt-4o",
        messages=messages,
        tools=tools,
    )
    print(final_response.choices[0].message.content)
```

```python
    retry=retry_if_exception_type((RateLimitError, APIConnectionError, APITimeoutError))
)
def call_openai(messages, **kwargs):
    """带重试的OpenAI调用"""
    try:
        response = client.chat.completions.create(
            model=kwargs.get("model", "gpt-4o"),
            messages=messages,
            **{k: v for k, v in kwargs.items() if k != "model"}
        )
        return response
    except RateLimitError as e:
        print(f"速率限制: {e}")
        raise
    except APIConnectionError as e:
        print(f"连接错误: {e}")
        raise
    except APIError as e:
        print(f"API错误: {e}")
        raise
```

#### 3.5.6 Token计算

```python
import tiktoken

def count_tokens(messages, model="gpt-4o"):
    """计算messages的token数量"""
    encoding = tiktoken.encoding_for_model(model)

    num_tokens = 0
    for message in messages:
        # 每条消息有固定开销
        num_tokens += 4  # <imstart>{role/name}\n{content}<imend>\n
        for key, value in message.items():
            num_tokens += len(encoding.encode(str(value)))
    num_tokens += 2  # 对话结束标记
    return num_tokens
```

```python
from abc import ABC, abstractmethod
from typing import List, Dict, Optional, Callable, Any
import json

class Tool:
    """工具基类"""
    def __init__(self, name: str, description: str, parameters: dict):
        self.name = name
        self.description = description
        self.parameters = parameters

    @abstractmethod
    def execute(self, **kwargs) -> str:
        pass

    def to_openai_format(self) -> dict:
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters
            }
        }

    def to_claude_format(self) -> dict:
        return {
            "name": self.name,
            "description": self.description,
            "input_schema": self.parameters
        }


class WeatherTool(Tool):
    def __init__(self):
        super().__init__(
            name="get_weather",
            description="获取指定城市的天气信息",
            parameters={
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "城市名称"}
                },
                "required": ["city"]
            }
        )

    def execute(self, city: str) -> str:
        # 实际项目中调用天气API
        weather_data = {
            "北京": {"temp": "25°C", "condition": "晴", "humidity": "45%"},
            "上海": {"temp": "28°C", "condition": "多云", "humidity": "65%"},
        }
        data = weather_data.get(city, {"temp": "22°C", "condition": "未知"})
        return json.dumps({"city": city, **data}, ensure_ascii=False)


class CalculatorTool(Tool):
    def __init__(self):
        super().__init__(
            name="calculator",
            description="执行数学计算，支持基本运算",
            parameters={
                "type": "object",
                "properties": {
                    "expression": {"type": "string", "description": "数学表达式"}
                },
                "required": ["expression"]
            }
        )

    def execute(self, expression: str) -> str:
        try:
            # 安全的数学计算
            result = eval(expression, {"__builtins__": {}}, {})
            return json.dumps({"expression": expression, "result": result})
        except Exception as e:
            return json.dumps({"error": str(e)})


class SearchTool(Tool):
    def __init__(self):
        super().__init__(
            name="search",
            description="搜索网络信息",
            parameters={
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "搜索关键词"}
                },
                "required": ["query"]
            }
        )

    def execute(self, query: str) -> str:
        # 实际项目中接入搜索API
        return json.dumps({
            "query": query,
            "results": [f"关于'{query}'的模拟搜索结果1", f"关于'{query}'的模拟搜索结果2"]
        }, ensure_ascii=False)


class LLMClient(ABC):
    """LLM客户端抽象基类"""

    def __init__(self, tools: List[Tool] = None):
        self.tools = tools or []
        self.messages: List[Dict] = []
        self.system_prompt = "你是一个有帮助的AI助手。"

    def set_role(self, role: str):
        """切换角色"""
        roles = {
            "assistant": "你是一个有帮助的AI助手，回答要准确、详细。",
            "translator": "你是一个专业翻译，将用户输入翻译为目标语言。如果用户没有指定，默认翻译为英文。",
            "coder": "你是一个编程专家，帮助用户解决编程问题。代码要包含注释和使用说明。",
        }
        self.system_prompt = roles.get(role, roles["assistant"])

    def set_output_format(self, fmt: str):
        """设置输出格式"""
        formats = {
            "json": "请以JSON格式输出。",
            "table": "请以Markdown表格格式输出。",
            "code": "请以代码块格式输出，包含语言标识。",
        }
        self.system_prompt += "\n" + formats.get(fmt, "")

    @abstractmethod
    def chat(self, user_message: str, stream: bool = False) -> str:
        pass

    @abstractmethod
    def _handle_tool_call(self, tool_name: str, tool_args: dict) -> str:
        pass

    def clear_history(self):
        """清除对话历史"""
        self.messages = []


class OpenAIClient(LLMClient):
    def __init__(self, tools: List[Tool] = None):
        super().__init__(tools)
        from openai import OpenAI
        self.client = OpenAI()
        self.tools_openai = [t.to_openai_format() for t in self.tools]
        self.tool_map = {t.name: t for t in self.tools}

    def chat(self, user_message: str, stream: bool = False) -> str:
        self.messages.append({"role": "user", "content": user_message})

        kwargs = {
            "model": "gpt-4o",
            "messages": [
                {"role": "system", "content": self.system_prompt},
                *self.messages
            ],
        }
        if self.tools_openai:
            kwargs["tools"] = self.tools_openai
            kwargs["tool_choice"] = "auto"

        if stream:
            # 流式输出
            response = self.client.chat.completions.create(stream=True, **kwargs)
            full_content = ""
            for chunk in response:
                if chunk.choices[0].delta.content:
                    print(chunk.choices[0].delta.content, end="", flush=True)
                    full_content += chunk.choices[0].delta.content
            print()
            return full_content
        else:
            response = self.client.chat.completions.create(**kwargs)
            msg = response.choices[0].message

            # 处理工具调用
            if msg.tool_calls:
                self.messages.append(msg)
                for tool_call in msg.tool_calls:
                    result = self._handle_tool_call(
                        tool_call.function.name,
                        json.loads(tool_call.function.arguments)
                    )
                    self.messages.append({
                        "role": "tool",
                        "tool_call_id": tool_call.id,
                        "content": result
                    })
                # 递归调用获取最终回答
                return self.chat("", stream=False)

            self.messages.append({"role": "assistant", "content": msg.content})
            return msg.content

    def _handle_tool_call(self, tool_name: str, tool_args: dict) -> str:
        tool = self.tool_map.get(tool_name)
        if tool:
            return tool.execute(**tool_args)
        return json.dumps({"error": f"Unknown tool: {tool_name}"})


class ClaudeClientAdapter(LLMClient):
    def __init__(self, tools: List[Tool] = None):
        super().__init__(tools)
        import anthropic
        self.client = anthropic.Anthropic()
        self.tools_claude = [t.to_claude_format() for t in self.tools]
        self.tool_map = {t.name: t for t in self.tools}

    def chat(self, user_message: str, stream: bool = False) -> str:
        if user_message:
            self.messages.append({"role": "user", "content": user_message})

        kwargs = {
            "model": "claude-sonnet-4-6",
            "max_tokens": 2048,
            "system": self.system_prompt,
            "messages": self.messages,
        }
        if self.tools_claude:
            kwargs["tools"] = self.tools_claude

        response = self.client.messages.create(**kwargs)

        # 处理工具调用
        if response.stop_reason == "tool_use":
            self.messages.append({"role": "assistant", "content": response.content})
            for block in response.content:
                if block.type == "tool_use":
                    result = self._handle_tool_call(block.name, block.input)
                    self.messages.append({
                        "role": "user",
                        "content": [{
                            "type": "tool_result",
                            "tool_use_id": block.id,
                            "content": result
                        }]
                    })
            return self.chat("", stream=False)

        text = response.content[0].text
        self.messages.append({"role": "assistant", "content": text})
        return text

    def _handle_tool_call(self, tool_name: str, tool_args: dict) -> str:
        tool = self.tool_map.get(tool_name)
        if tool:
            return tool.execute(**tool_args)
        return json.dumps({"error": f"Unknown tool: {tool_name}"})
```

## 六、自测题

### 题目

1. **GPT和BERT的架构区别？各自擅长什么任务？**

<details>
<summary>参考答案</summary>

GPT是Decoder-Only架构，使用单向（因果）注意力，只能看到前文，擅长文本生成任务（对话、写作、代码生成）。BERT是Encoder-Only架构，使用双向注意力，能看到前后文，擅长文本理解任务（分类、NER、阅读理解）。现代LLM几乎都采用GPT的Decoder-Only架构。
</details>

2. **BPE分词的基本步骤？**

<details>
<summary>参考答案</summary>

(1) 初始化基础词表为所有单个字符；(2) 在训练语料上统计所有相邻token对的频率；(3) 找到频率最高的pair，合并为新的token加入词表；(4) 重复步骤2-3直到词表大小达到预设值。BPE的核心优势是能自动学习常见的子词组合，平衡词表大小和表达力。
</details>

3. **CoT为什么能提升推理能力？**

<details>
<summary>参考答案</summary>

CoT通过要求模型"一步一步思考"，将复杂问题分解为多个简单步骤：(1) 每一步的计算量更小，降低了单步推理的难度；(2) 中间步骤的生成为最终答案提供了更多计算步骤（更多forward pass）；(3) 显式的推理过程减少了跳步和遗漏的可能性；(4) 类似于人类解复杂问题时的草稿纸。
</details>

4. **Function Calling的工作流程？**

<details>
<summary>参考答案</summary>

(1) 开发者定义工具的JSON Schema（名称、描述、参数）；(2) 用户提问，将问题+工具定义一起发送给LLM；(3) LLM判断是否需要调用工具，如果需要，返回工具名称和参数；(4) 开发者执行实际工具函数，获得结果；(5) 将工具结果返回给LLM；(6) LLM根据工具结果生成最终回答。整个过程可能循环多次。
</details>

5. **Prompt Caching如何节省成本？**

<details>
<summary>参考答案</summary>

Prompt Caching将系统提示等重复内容在服务端缓存（标记为cache_control: ephemeral），5分钟内的后续请求如果包含相同的缓存前缀，可以直接读取缓存，无需重新计算。缓存的token价格通常比正常输入token便宜90%。适合场景：长系统提示、大量上下文文档、高频重复对话模式。
</details>

### Function Calling类比

```
Function Calling ≈ Java反射机制

Java反射：通过字符串方法名，动态调用对象的方法
  Method method = obj.getClass().getMethod("getWeather", String.class);
  Object result = method.invoke(obj, "北京");

Function Calling：LLM输出方法名和参数字符串，你的代码动态调用对应函数
  LLM输出: {"name": "get_weather", "arguments": {"city": "北京"}}
  你的代码: tool_map["get_weather"].execute(city="北京")

两者都是"根据字符串动态路由到具体方法"
```

```
Prompt模板 ≈ Java模板引擎（Freemarker/Thymeleaf）

Prompt模板：
```

### Token类比

```
Token ≈ Java中的String长度计算，但不完全等同

Java: "Hello World".length() = 11 (字符数)
Token: "Hello World" → [Hello, World] = 2 tokens

注意：中文的token效率更低
"你好世界" → 可能是 4-6 个tokens
而英文字母共52个，但BPE词表通常10万+
```
